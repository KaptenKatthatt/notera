# Notera backlog

Brain dump of ideas, in the order they were said. Not prioritised yet.

- [ ] Change the text width without resizing the window, modelled on VS Code's centered layout. The toggle is done: "Narrow text column" in the View menu and Settings, on by default, centres the text at 66 characters with the sidebar and preview still there. Left to do:
  - A shortcut for the toggle.
  - Resize: the column's edges show on hover, and dragging either edge changes the width. Both edges move together so the text stays centred. Double-clicking an edge resets it to 66.
  - Storage: the width is saved in characters, not pixels, so it looks the same after Ctrl+Plus and when the window is resized. A window narrower than the column just fills the window.
  - Writing mode uses the same width, so it is set in one place.
- [ ] Theme gallery: browse and install community themes in one click, fetched from a GitHub repo. Later, once other people have made themes worth showing. Builds on the themes folder (`%APPDATA%/Notera/themes/<theme>/` with `theme.json`, optional `style.css`, `fonts/`, images) that reloads on save, decided in the theme design grilling 2026-09-30.
- [ ] Look at shipping a small set of standard fonts that any theme can refer to by name (e.g. a few OFL heading and monospace faces). Not yet: for now every theme carries its own fonts in its `fonts/` folder, decided in the theme design grilling 2026-09-30.
- [ ] A Theme tab in Settings where you change the current theme's properties without touching code or `theme.json` by hand: e.g. pick the cursor animation (phosphor, trail, sparks, ripple, pulse, none), switch glow on or off and set its strength, pick colours, fonts, the background grid and sun. Changes show live in the editor behind the dialog. The tab is generated from what the theme format supports (the effect list and parameters in `theme.schema.json` / `normalizeEffects`), so a new effect or parameter shows up in the tab without UI code of its own. It writes to the theme's `theme.json`; a built-in theme is copied to a user theme first ("New theme from current"), so the originals stay intact. Replaces the earlier "visual theme editor, later" item from the theme design grilling 2026-09-30; Jonas wants it now.
- [ ] Search and download VS Code themes by name from Open VSX (open-vsx.org), not Microsoft's Visual Studio Marketplace, whose terms limit its extensions to Microsoft products. Pair it with the theme gallery, since both fetch themes over the network. v1 imports from the local VS Code install (`%USERPROFILE%\.vscode\extensions`) and from `.vsix` files, decided in the theme design grilling 2026-09-30.
- [ ] The templates section in the sidebar can be collapsed, like a project: a chevron on the "Templates" header folds the list away and shows the count while it is folded. The folded state is remembered across restarts, the way projects remember theirs.
- [ ] Bug: with word wrap on, the continuation of a wrapped indented line starts at the left edge instead of under the line's own start. E.g. an indented `  - Hitta…` list item wraps and its second visual line ("Fixade.") starts further left than the first, so the two lines do not read as one. Wrapped lines should keep the line's indentation, the way VS Code wraps code (`wrappingIndent: "same"`). Photo: [backlog-wrap-indent.jpg](backlog-wrap-indent.jpg).
- [ ] Cursor effect is its own setting, not part of a theme: pick the theme and the cursor effect separately, and any cursor effect works with any theme (or "None"). Lives in the Theme tab in Settings (item above) and probably the command palette. The effects come from the cursor lab (https://claude.ai/artifact/FescY3WNsQpTeAYHnu7xmV): Jonas picked these ten to ship (2026-10-01), Swedish lab names in brackets: sparks (Fyrverkeri), pixie dust (Älvstoft), ripple (Ringar), pulse (Pulserande markör), phosphor letter (Fosforbokstav), red laser (Röd laser), laser sight (Lasersikte), neon tube (Neonrör), glitch (Glitch), focus/blur-in (Skärpa), plus None. Not offered: the phosphor + trail combination, trail on its own, falling sparks and shake. Neon OMG uses phosphor + trail since #28, so its suggested default changes to one of the ten (phosphor is the natural pick); the trail code from #28 can go unless something else uses it. A theme may still suggest a default cursor effect, but the user's choice wins and survives a theme switch. Colours follow the active theme (caret colour, accent) unless the effect has its own, like the red laser.
- [ ] The cursor and theme effects are heavy to run: typing with them on is sluggish. Profile first (DevTools Performance while typing in Neon OMG, effects on vs off via View > Theme > Theme effects), then fix what the profile shows. Suspects in `src/renderer/effects.js` and the `fx-*` rules in `styles.css`:
  - The particle and trail canvas covers the whole window at full `devicePixelRatio`, and every particle is drawn with `shadowBlur`, which is slow. The cursor lab got much lighter by drawing a pre-rendered glow sprite with `drawImage` instead, and by drawing the canvas at 1× (the glow is soft anyway).
  - `fx-e-glow-all` puts an 18–34 px `text-shadow` on all of `.cm-content`, so every repaint of the editor (each keystroke, each frame of the phosphor animation) repaints blurred text.
  - The phosphor animation animates `text-shadow`, which repaints every frame for 0.55 s per keystroke; compare an opacity-only overlay.
  - The moving background grid (`fx-grid-run`) animates `background-position`, a repaint every frame even when nobody types; move it to a composited layer (`transform` on a pseudo-element) or stop it while typing.
  - Measure and draw only while something moves; stop the frame loop when idle.
  - Target: typing feels the same with effects on as off on an ordinary laptop, measured, not guessed.
