# Notera backlog

Brain dump of ideas, in the order they were said. Not prioritised yet.

- [x] Bug: the Theme submenu shows two selected radio buttons at once, e.g. "Follow system" and "Those guys". Rebuild it as two independent choices with exactly one pick each. At the top, the themes: Default, Those guys, The Other guys. Default is a theme of its own, like the other two. Below the line, the mode: Follow system, Light, Dark. The mode is only a switch between the light and dark version of the selected theme; it never switches to Default's light or dark version. So every theme, now and later, must ship both a light and a dark version (today Those guys and The Other guys are dark only). Screenshot: [backlog-theme-menu.png](backlog-theme-menu.png). Done in #19.
- [ ] Change the text width without resizing the window, modelled on VS Code's centered layout. Writing mode already centres a fixed 66ch column but hides the sidebar and preview, and its width cannot be changed.
  - Toggle: "Narrow text column" in the View menu, with a shortcut, on by default. The text is centred at 66 characters; the sidebar and preview stay.
  - Resize: the column's edges show on hover, and dragging either edge changes the width. Both edges move together so the text stays centred. Double-clicking an edge resets it to 66.
  - Storage: the width is saved in characters, not pixels, so it looks the same after Ctrl+Plus and when the window is resized. A window narrower than the column just fills the window.
  - Writing mode uses the same width, so it is set in one place.
- [ ] Theme gallery: browse and install community themes in one click, fetched from a GitHub repo. Later, once other people have made themes worth showing. Builds on the themes folder (`%APPDATA%/Notera/themes/<theme>/` with `theme.json`, optional `style.css`, `fonts/`, images) that reloads on save, decided in the theme design grilling 2026-09-30.
- [ ] Look at shipping a small set of standard fonts that any theme can refer to by name (e.g. a few OFL heading and monospace faces). Not yet: for now every theme carries its own fonts in its `fonts/` folder, decided in the theme design grilling 2026-09-30.
- [ ] A Theme tab in Settings where you change the current theme's properties without touching code or `theme.json` by hand: e.g. pick the cursor animation (phosphor, trail, sparks, ripple, pulse, none), switch glow on or off and set its strength, pick colours, fonts, the background grid and sun. Changes show live in the editor behind the dialog. The tab is generated from what the theme format supports (the effect list and parameters in `theme.schema.json` / `normalizeEffects`), so a new effect or parameter shows up in the tab without UI code of its own. It writes to the theme's `theme.json`; a built-in theme is copied to a user theme first ("New theme from current"), so the originals stay intact. Replaces the earlier "visual theme editor, later" item from the theme design grilling 2026-09-30; Jonas wants it now.
- [ ] Search and download VS Code themes by name from Open VSX (open-vsx.org), not Microsoft's Visual Studio Marketplace, whose terms limit its extensions to Microsoft products. Pair it with the theme gallery, since both fetch themes over the network. v1 imports from the local VS Code install (`%USERPROFILE%\.vscode\extensions`) and from `.vsix` files, decided in the theme design grilling 2026-09-30.

- [ ] Bug: with word wrap on, the continuation of a wrapped indented line starts at the left edge instead of under the line's own start. E.g. an indented `  - Hitta…` list item wraps and its second visual line ("Fixade.") starts further left than the first, so the two lines do not read as one. Wrapped lines should keep the line's indentation, the way VS Code wraps code (`wrappingIndent: "same"`). Photo: [backlog-wrap-indent.jpg](backlog-wrap-indent.jpg).
- [ ] Neon OMG: the typing sparks (`notera.effects.particles`, burst in `src/renderer/effects.js`) cover the text being typed, so you cannot see what you write. Each keystroke sends 10 sparks upward in a ~200° fan for 30–70 frames, over the current and previous lines. Pick a replacement or tone it down. Options (prior art in brackets):
  - Sparks fall down and away from the line instead of up, fewer and shorter-lived, like a welding torch. Smallest change.
  - Pixie dust: 2–3 tiny dots that drift a few pixels and fade within one line height (Neovide `pixiedust`).
  - Ripple / sonic boom: a thin ring expands from the caret and fades in ~200 ms, transparent in the middle (Neovide `ripple`, `sonicboom`).
  - Cursor trail: a fading streak follows the caret when it moves or jumps, barely visible while typing (Kitty `cursor_trail`, Ghostty's cursor smear shader, Neovide `railgun`/`torpedo`). Fits the existing smooth cursor.
  - Caret pulse: the caret's glow flashes brighter on each keystroke and decays. Draws nothing outside the caret.
  - Phosphor letter: the character just typed flashes with extra glow and settles to the normal glow, like a CRT. The letter itself is the effect, so nothing covers it.
- [ ] Cursor effect is its own setting, not part of a theme: pick the theme and the cursor effect separately, and any cursor effect works with any theme (or "None"). Lives in the Theme tab in Settings (item above) and probably the command palette. The effects come from the cursor lab (https://claude.ai/artifact/FescY3WNsQpTeAYHnu7xmV): phosphor, trail, sparks, falling sparks, pixie dust, ripple, pulse, red laser, laser sight, neon tube, glitch, focus, shake. Jonas will say which ones to ship. A theme may still suggest a default cursor effect, but the user's choice wins and survives a theme switch. Colours follow the active theme (caret colour, accent) unless the effect has its own, like the red laser.
